# Build log (one line per session: the date, what shipped, what I learned)

- 2026-11-15: Dockerfile (ADR-001), Kubernetes manifests with TLS through Traefik and cert-manager (ADR-002), and kind scripts to set up, deploy and smoke-test. Verified on a local kind cluster: HTTPS 200 with a verified certificate, HTTP redirects to HTTPS, and the NetworkPolicy blocks other namespaces. Learned: wisecow serves one connection at a time, so it needs two replicas; when a Deployment shows no events, check the control plane before the manifest; under `set -e`, `read` fails on input without a trailing newline.
- 2026-11-15 (later): CI/CD pipeline (ADR-003). Lint, then a multi-arch build pushed to GHCR with GITHUB_TOKEN, then a deploy by digest to a kind cluster inside the runner that pulls from GHCR with a pull secret. First run passed end to end in 3 min 12 s, and both pods ran the exact pushed digest. Learned: hosted runners can't reach a laptop cluster; a digest names exactly one image while a tag can move; new GHCR packages are private, so the cluster needs credentials to pull.
- 2026-11-15 (later): Recreated the repository to clean up its commit history. Its first build was refused (`permission_denied: write_package`) because the old GHCR package still existed; deleted the package, reran the failed jobs, and the pipeline passed. Learned: a GHCR package outlives its repository.
- 2026-11-16: Problem Statement 2 (ADR-004). A run-once system health monitor (CPU from two `/proc/stat` reads, memory from MemAvailable, disk, processes) and an app health checker (2xx up, everything else down), both Bash, reporting through a log file and exit code. Tested on Linux and macOS; the pipeline now lints both and runs the checker against each deployment. Learned: CPU usage needs two samples; a 301 isn't "up"; the checker caught a real outage on the overloaded local cluster.
- 2026-11-16 (later): Moved the repo to ~/projects/wisecow and reviewed the README and ADRs as a reviewer would. Fixed twelve issues: a wrong cross-reference, overstated claims in ADR-002, an unsourced claim (now linked to the Kubernetes announcement), `kubectl apply -k k8s` needing cert-manager and Traefik, the CI diagram missing the app check, and an unpinned ShellCheck (now pinned by digest). Correction to the CI/CD entry: the GHCR package came out public, so an anonymous pull works; the pull secret is a safeguard, not a requirement. Learned: check doc claims against the code or a real request.
- 2026-11-16 (later): Reviewed the project story the same way. "Builds reproducibly" was an overclaim (apt isn't pinned and labels carry the commit and time), the probe obstacle was inferred rather than observed, and the story now has a Known limits list and the CI checker result. Open question: the liveness probe restarted slow pods during the local outage.
